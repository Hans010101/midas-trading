## 1.3 后端设计(★性能是关键)

**性能事实**:`select_kline` 是单标的单 query(无批量接口)。A股 5500 只全市场逐只读 K线算指标 = 5500 queries,串行 ~275s(不可接受),并发16 ~17s(勉强)。

**推荐分层方案(成本由低到高,先做 A+C):**

- **方案A · 轻量预筛(秒级·先做)**:价格/涨跌幅/成交量/成交额/板块 这些**不需要读 K线**,直接 `SELECT ... WHERE ... ORDER BY ... LIMIT` 打 spot 快照表(全市场 5500 行 <10ms)。覆盖条件 ⑥⑦⑧⑨ + 板块。
- **方案C · 批量 K线接口(必补)**:新增 `select_klines_batch(symbols, ...)`(ClickHouse `LIMIT N BY symbol` 单 query),把"算指标"从 N queries 降到 1 query。预筛后的候选(几十只)再批量拉 K线算 RSI/MA/MACD。
- **方案B · 指标快照表(中期优化)**:`cn_indicator_snapshot`(日更预计算 ma/rsi/macd/%b),Celery beat 收盘后跑一次(~55s),查询变秒级。第一版可不做,量大时再上。
- **方案E · Redis 缓存**:热门筛选组合缓存(借 `boll_scan` 快照范式),5min TTL。

**筛选服务组织**(复用现有范式):预筛(快照)→ 候选 symbol 列表 → 按需批量算指标 → 匹配条件 → 分页返回。遍历范式照搬 `boll_scan.py`(universe + 逐标 + Redis 快照)。

**端点**:`POST /api/v1/{market}/screener`(filters + sort + limit/offset 分页)。

## 1.4 前端设计

- **筛选页**(新路由,如 `/screener` 或挂市场首页 tab):条件选择 UI(分组:价格/涨跌幅/成交量 → 快;技术指标 RSI/MA/MACD/布林 → 需预筛后算;板块下拉;缠论开关)。
- **结果列表**:代码/名称/最新价/涨跌幅/成交额/命中的指标值,点行 → 新标签开详情页(复用现有 `/cn-preview` 等)。
- **分页/流式**:先 20 条,滚动加载(方案D)。
- 复用现有榜单/搜索组件范式(`market-home/*-sections.tsx` 已有榜单+搜索+点击跳详情)。

## 1.5 ★红线落地

- 结果区标题/文案:**"符合条件的股票"**(客观筛选结果),**绝不**"推荐买入/精选牛股"。
- 每页底部免责:"以上为按你设定条件的客观筛选结果,仅供参考,不构成投资建议。"
- 纯客观数据展示(命中的指标值=事实),不加方向性结论、不排"推荐度"。
- 全程只读行情数据,不触发任何下单。

## 1.6 加密复用可行性(四市场通用)

- 指标引擎/缠论**市场无感**,同一筛选器**现货四市场(cn/us/hk/crypto spot)天然通用**。
- 加密的"现货筛选"可复用;但加密主体是 **perp**(永续,走另一套引擎+有 OI/资金费/多空比 等独有维度),perp 筛选维度更丰富(可加资金费/OI 条件),但那是**加密专属扩展**,不在"四市场通用筛选器"范围。
- ★拍板点:第一版筛选器是否同时上加密现货?(技术上几乎零额外成本,但加密用户更关心 perp 维度,价值待定。)

# 功能3 · 港股告警补齐(对称 cn/us · 受港股数据限制)

## 3.1 现有实现盘点
- **注册表** `alerts/registry.py:229-265`:`_ALL=(cn,us,crypto)`、`_CN_US`、`_CRYPTO` —— **无 hk 组合**。
- **规则模型/schema**:`alert_rule.py` schema **已支持 hk**(`RuleMarket = Literal[cn,us,crypto,hk]`),只是没指标分配给 hk。
- **扫描** `alert_scan.py:74-157`:按 category 分频扫(价格/技术 1min、衍生 5min、市场结构 3min、缠论 30min),**市场无关**(只要 registry+fetcher 对就自动工作)。
- **推送**:命中 → TG(N1 边沿触发已内置)。

## 3.2 港股扩展点(改动集中在 registry.py·~2h)
- 加市场组合:`_ALL_HK=(cn,us,crypto,hk)`、`_CN_US_HK=(cn,us,hk)`。
- 把 price/change_pct/volume/ma_*/macd/rsi/boll/chan 的 markets 从 `_ALL` 改 `_ALL_HK`。
- 新增 `_f_hk_breadth_up_ratio`(读 `hk_market_breadth`,港股无涨跌停,分母=up+down)。
- `sector_change_pct` fetcher 加 hk 分支(`clickhouse_hk_market.select_latest_sectors`)。
- **`alert_scan.py` / 路由 / 引擎 无需改**(市场无关)。

## 3.3 ★港股数据限制对告警的影响(诚实)

| 指标 | 港股可否 | 说明 |
|---|---|---|
| price / price_change_pct / volume | ✅ | spot 快照支撑 |
| MA / MACD / RSI / 布林%B | ✅(日线) | **港股 K线日线深度充足**(akshare stock_hk_daily 完整历史;注:与现状盘点"~18根"有出入——18 根是 yfinance 备用源,主源新浪日线深度够,★需复核确认生产用哪个源) |
| hk_breadth_up_ratio | ✅ | hk_market_breadth(无涨跌停,阈值要放宽) |
| 缠论 chan_buy/sell | ⚠️ | 日线可跑,但**无分钟线 → 灵敏度打折**,建议标注"港股缠论基于日线" |
| sector_change_pct | ⚠️ 待确认 | hk_sector(yfinance GICS)聚合是否完整 |
| index_change_pct(恒指告警) | ❌ | **港股无指数数据采集**(market_index_snapshot 无 hk 行),要支持需补恒指采集 |

**港股第一版告警可交付指标子集(8个)**:price / change_pct / volume / ma_* / macd / rsi / boll%B / hk_breadth。缠论(日线·灵敏度提示)、板块(待确认聚合)列第二批;恒指告警需补数据源(另评估)。

## 3.4 红线
告警 = **"你设的条件已达成"客观事实通知**(如"腾讯 RSI 触及 75"),**非买入/卖出信号**;推送文案不含方向建议。
