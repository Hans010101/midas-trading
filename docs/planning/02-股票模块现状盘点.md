# 点金 Midas 股票模块(A股/港股/美股)现状盘点

> 只读代码调研(6 路并行 + 文件:行号取证),未改任何代码、未碰 PR-8 分支。
> 诚实声明:没有的功能明确标"无";两路 agent 对**港股下单激活状态**有分歧,已标"需复核";数据源限制如实写。

## 一句话总览

**前端 + 现货虚拟交易引擎是四市场(cn/us/hk/crypto)100% 参数化共用的;股票三市场已有 K线/缠论/指标/AI决策卡/策略信号/虚拟下单的完整"分析+虚拟交易"闭环。但加密侧的"高级玩法"(永续合约维度、智能交易、托管、布林做T、结构诊断)是硬编码 `market=="crypto"` 的独立系统,股票侧没有、也不能直接扩;股票侧明显缺的是【选股/筛选器】【A股特有数据:龙虎榜/北向/财务】【港股告警与全市场覆盖】。**

## 二、功能层(对照加密侧)

### 2.1 股票侧【已有】

- **K线图**:四市场共用 `KlineChart`,cn/us 1d/1h/15m 可切,hk 1d/1w。
- **技术指标**:MA/MACD/RSI/KDJ/BOLL/ATR/量比 —— **指标引擎纯算法、市场无感**,股票完全可用(`apps/api/app/services/ai/indicators.py`)。
- **缠论**:笔/分型/中枢,cn/us/hk/crypto **全支持**(`/analysis/chan`)。
- **AI 决策卡**:综合评分+解读+缠论买卖点+actionable,cn/us/hk **全支持**(`/analysis/decision-card`,Pro 门控,免费返 locked 空壳)。
- **策略信号**:`ma_cross/rsi_reversal/boll_reversion`(extreme 仅 crypto),cn/us/hk 支持;**CN/US 详情页默认关闭(产品决策)、港股默认打开**。
- **策略推荐**:纯规则(趋势→均线/震荡→RSI/贴轨→均值回归),全市场支持。
- **市场首页**:cn(全市场榜单+情绪条+24 板块热力图+全市场搜索)、us(策展池榜单+11 板块+中概+本地搜索)、hk(~900 榜单+情绪条+GICS 板块+本地搜索,诚实标"主要成分非全市场")。
- **详情页**:cn/us/hk 共用 `SpotDetail`(K线+布林+MACD+缠论标注+策略面板+AI 决策卡+虚拟下单区+条件单列表)。
- **虚拟下单**:cn 纯做多(T+1,100 股/手)、us 做多+卖空(无杠杆 1:1 锁现金)、hk 按手取整(board lot,T+0,印花税/佣金)。
- **告警规则**:cn/us 价格+指标(MA/MACD/RSI/Boll%B/缠论)预警→TG 推送。
- **自选股 / 投资组合 / 权益曲线 / AI 历史命中率**:全市场聚合。

## 三、架构层(★最关键结论)

### 3.1 共用 vs 独立 一览

| 层 | 共用 / 独立 | 股票可扩性 |
|---|---|---|
| 前端路由 + K线组件 + 市场切换 | **100% 共用**(market 一级参数,零硬编码) | ✅ 现成 |
| 现货虚拟交易引擎 `place_market_order` | **四市场共用**(cn/us/hk/crypto,market 参数化;hk 按手、us 卖空是隔离分支) | ✅ 现成 |
| 指标引擎 / 缠论 / 决策卡 / 策略信号 / 策略推荐 | **共用·市场无感** | ✅ 现成 |
| 条件单框架 `conditional_trigger` | **框架通用**(代码已含 cn/us/hk 分支,价源现货 vs 永续区分)·股票分支基础设施齐备**但 UI 未启用** | ✅ 低成本(差 UI+启用) |
| **永续合约引擎 `perp_engine`** | **彻底独立·写死 `_CRYPTO_MARKET="crypto"`** | ❌ 不可参数化 |
| **智能交易** | 写死 `INTELLIGENT_MARKET="crypto"` + 系统账户走 `route_open_perp` | ❌ 要扩股票=建股票 SHORT 引擎+系统用户(架构级重组) |
| **托管交易** | 写死 `MANAGED_MARKET="crypto"` | ❌ 同上 |
| **布林做T** | 写死 crypto perp universe(Top 150)+ `instrument="perp"` | ⚠️ 指标通用,但 universe 要换 + T+1 概念碰撞 |

### 3.2 含义
- **加密侧能力能直接复用到股票的**:指标引擎、缠论、决策卡、策略信号/推荐、现货虚拟下单、条件单框架 —— 这些都是 market 参数化的,股票扩展**几乎零架构成本**。
- **不能直接复用的**:永续合约 + 智能/托管/做T —— 它们写死 crypto,且依赖合约衍生品(资金费/OI/强平/做空)和 T+0 高频,**和股票现货+T+1 在交易学上就不同**,是设计选择而非疏漏。

## 四、已知限制 / 缺口

### 4.1 数据源限制(成本/实时性/覆盖)
- **美股非全市场**:仅 ~128 只策展池(产品定位,不是 bug)。
- **港股非全市场**:榜单/搜索 ~900 只(新浪限页防封 IP),K线深度采集仅 ~18 只策展;港股 K线主源(新浪)仍探测阶段,yfinance 备用。
- **港股无分钟线**:数据源限制,只有 1d/1w。
- **A股特有数据全缺**:龙虎榜/北向资金/财务 未接。
- 实时性都是**收盘后日终/轮询延迟**,无实时 tick(加密 Roadmap 提过 WebSocket 升级,股票未规划)。

### 4.2 功能缺口(对照成熟股票软件)
1. **选股/条件筛选器** —— 最大空白(成熟股票软件的核心,点金股票侧完全没有)。
2. **A股特有数据维度** —— 龙虎榜/北向/财务/资金流。
3. **港股告警 + 港股全市场覆盖**。
4. 板块热力图色块不可点(cn/us 仅视觉,无板块详情页)。

### 4.3 ★一处需复核的分歧(诚实标注)
- **港股虚拟下单/AI卡 是否已激活**:前端 agent 看到 hk 详情页"阶段三 gate 已解除"(AI卡/策略/下单都打开);后端/红线 agent 看到 `hk.py` 路由注释"全部 GET·只读·不碰下单(港股阶段三)" + `virtual.py` 港股下单代码就绪但疑未启用端点。**两路结论冲突**——可能是"代码已合但产品 gate 状态"或"前后端不同步"。**需实机访问 hk-preview 页确认港股能否真下单**(memory 记录港股阶段三 AI卡/策略/虚拟下单已合 main 部署,倾向"已激活",但代码注释存歧义,标"需复核")。

## 五、★虚拟红线在股票模块怎么落地的

**两条红线在股票侧都已落地,且和加密走同一套机制:**

### 5.1 全程虚拟、绝不真实下单
- 股票走 `VirtualAccount`(每用户每市场一行,`market` ∈ cn/us/hk/crypto,原币种 CNY/USD/HKD/USDT,不折算),撮合走 `place_market_order` 虚拟引擎(滑点/手续费/流动性按 market 计算),**全链路无任何真实交易 API**。
- 前端各市场详情页明确声明:cn "永远只用虚拟资金·绝不接真实交易通道"、us "卖空只是虚拟负持仓记账"、hk "复用虚拟引擎,与 A股/美股同口径"。
- 费率虚拟扣(cn 0.03%买+0.13%卖、hk 0.2%双边、us 0%),无实汇兑。

### 5.2 分析非建议、仅供参考
- **AI 决策卡**走 `validator.py`:严格模式 `rewrite_imperatives`(祈使句改陈述:"建议买入"→"分析显示买入信号")+ `validate_advisory`(AI 模拟下单模式放开 actionable 但 `scrub_marketing` 清"稳赚/保本/无风险"违规营销)。
- **免责文案**:复盘"⚠ 本复盘仅供参考,不构成投资建议"、布林推送"· 仅供参考"、结构描述"非建议·仅供参考",且有**合规门禁**(无声明一票否决)。
- 股票 AI 卡和加密共用同一 workflow + validator,**红线机制天然覆盖股票三市场**。

## 六、给 Hans 的收口(承接"用股票软件成熟功能丰富股票模块")

**好消息**:点金股票模块的**地基已经很扎实**(数据/K线/指标/缠论/AI卡/虚拟下单/红线全有,且四市场参数化共用)——丰富股票模块不需要重建框架,是在现成地基上加"工具能力"。

**对照前一份《战略家竞品分析》,最契合"借鉴 + 填股票缺口"的方向**(均可复用现成基建、守住红线):
1. **选股/条件筛选器** —— 股票侧最大空白 + 战略家核心工具能力;复用指标引擎(全市场无感)+ ClickHouse,输出"符合条件的标的列表"(事实非荐股)。**填空白 + 可借鉴,优先级最高。**
2. **港股告警补齐 + A股特有数据(龙虎榜/北向)** —— 告警框架已有(只差 hk 注册 + 数据源);龙虎榜/北向是 A股选股维度,需接数据源(成本待评估)。
3. **条件单 UI 启用到股票** —— 框架已支持 cn/us/hk 分支,只差前端入口,**最低成本**。
