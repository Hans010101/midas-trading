# Midas Trading 域名与用户无感切换运行手册

本手册只操作 `midas-trading`（Cloudflare）项目。旧点金 Midas 与阿里云在最终 DNS 切换前始终只读运行。

## 切换前门槛

- Cloudflare API、Web、D1 migration、定时任务和生产 smoke 全部通过。
- `/api/v1/*` 不再回落到旧 `api.midastrade.asia`。
- 管理后台迁移中心至少导入旧用户 ID 与邮箱，预演为零冲突。
- Google OAuth 已加入最终域名的 redirect URI；Resend 已验证最终发信域名。
- 已记录 D1 Time Travel bookmark、旧库只读快照时间和 DNS 原 TTL。
- 核对旧用户总数、迁移邮箱数与抽样登录结果。

## 本次最小迁移范围

- **硬门槛只有两项：**旧域名切换到 Cloudflare；旧用户能够用原 Google 邮箱直接登录，不需要重新注册。
- 对 Google 用户，迁移数据只要求 `legacy_user_id` 与规范化邮箱。`google_sub` 可以不从旧系统导出；首次 Google 登录时，新平台会按邮箱匹配并绑定已验证的 Google 身份。
- 旧站登录 Cookie/Session 不跨系统复制。域名切换后用户可能需要重新点击一次“使用 Google 登录”，但不会创建重复账户，也不需要重新填写注册资料。
- 所有功能当前免费开放，不迁移会员等级、套餐、余额、兑换码、邀请奖励或功能权限。
- 自选收藏、提醒规则、训练营进度、模拟账户、持仓与订单历史均为可选迁移项，不阻塞域名切换；本次可以全部跳过。

## 用户迁移顺序

1. 导出旧系统用户的 `legacy_user_id`、邮箱及可选昵称；Google 用户不要求旧密码或旧会话。
2. 每批最多 25 人，先预演，再正式导入；失败批次停止后续批次。
3. 抽样使用原 Google 邮箱登录，确认绑定到预导入用户 ID，且不会新建第二个邮箱相同的账户。
4. 少量纯密码用户不复制旧 Argon2 密码；引导其使用同邮箱 Google 登录，或单独发送重置密码邮件。
5. Telegram、飞书使用新项目机器人，旧绑定不直接复用，用户按需重新绑定。
6. 自选、提醒、训练营和模拟交易记录仅在后续确有需求时再追加迁移。

## 切换窗口

1. 将旧系统用户写操作切为只读，记录最终增量时间点。
2. 迁移最后新增用户并完成邮箱数量、冲突检查与重点账户抽样。
3. 将最终域名绑定到 Cloudflare Web/API，并更新 OAuth、Resend 与 CORS 配置。
4. 将 DNS TTL 降低后切换；旧阿里云继续只读保留至少 7 天。
5. 优先验证原 Google 用户登录与重复账户检查，再验证行情、财经日历、提醒、通知、模拟交易、回测和管理员后台。

## 回滚条件

- 登录成功率、核心 API 错误率或数据完整性出现严重异常。
- 新旧用户映射存在不可解释冲突。
- 原邮箱被创建为重复账户，或登录成功率出现严重异常。

回滚时恢复原 DNS，停止新平台写入，并使用切换前 D1 Time Travel bookmark 恢复。不得双向合并两个平台在切换窗口后的写入。
