# Midas Trading 域名与用户无感切换运行手册

本手册只操作 `midas-trading`（Cloudflare）项目。旧点金 Midas 与阿里云在最终 DNS 切换前始终只读运行。

## 切换前门槛

- Cloudflare API、Web、D1 migration、定时任务和生产 smoke 全部通过。
- `/api/v1/*` 不再回落到旧 `api.midastrade.asia`。
- 管理后台迁移中心的用户批次预演为零冲突。
- Google OAuth 已加入最终域名的 redirect URI；Resend 已验证最终发信域名。
- 已记录 D1 Time Travel bookmark、旧库只读快照时间和 DNS 原 TTL。
- 核对用户数、自选数、提醒规则数、训练营进度数与抽样校验和。

## 用户迁移顺序

1. 先迁移 Google 用户、个人偏好、自选、提醒规则和训练营进度。
2. 再迁移模拟账户、持仓和订单历史；迁移批次必须保留 legacy id。
3. 密码用户不复制旧 Argon2 密码到新 scrypt 体系；提前发送重置密码邮件。
4. Telegram、飞书使用新项目机器人，旧绑定不直接复用，用户在新平台重新绑定。
5. 每批最多 25 人，先预演，再正式导入；失败批次停止后续批次。

## 切换窗口

1. 将旧系统用户写操作切为只读，记录最终增量时间点。
2. 迁移最后增量并完成数量、校验和与重点账户抽样。
3. 将最终域名绑定到 Cloudflare Web/API，并更新 OAuth、Resend 与 CORS 配置。
4. 将 DNS TTL 降低后切换；旧阿里云继续只读保留至少 7 天。
5. 验证登录、注册、行情、财经日历、提醒、通知、模拟交易、回测、管理员后台。

## 回滚条件

- 登录成功率、核心 API 错误率或数据完整性出现严重异常。
- 新旧用户映射存在不可解释冲突。
- 模拟资产/持仓抽样不一致，或提醒发生重复风暴。

回滚时恢复原 DNS，停止新平台写入，并使用切换前 D1 Time Travel bookmark 恢复。不得双向合并两个平台在切换窗口后的写入。
