# 点金 Midas 全站国际化(中英双语)· 只读调研报告

> 目标:海外用户、英文地道(交易术语准)· 静态 UI + 面向用户的动态 AI 内容全英文化 · 排除币安广场/X 发文 · 只读调研不写码。
> 方法:10-agent 并行调研(9 路代码/web + 1 路综合)+ DeepSeek 英文能力单独补研 · 全程 grep/read/web,零代码改动。
> ★诚实基调:规模如实统计、DeepSeek 英文如实评估(不高估)、翻译工作量不低估。

## 〇、结论先行(给 Hans 的一页纸)

1. **可做、有清晰路径,但这是"暗黑模式 × 3"级别的大工程**,必须分 6 阶段、每段独立可交付。
2. **静态文案量可控**(前端 ~717 条唯一 UI 文案 + 后端仅 ~116 条用户可见);**两个真正的大头是**:① **动态 AI 双语**(系统工程 + 合规红线,不是"翻译一下")② **训练营存量翻译**(实测 ~35-40 万字)。
3. **框架**:next-intl(Next 15 App Router + React 19 天然契合)· **路由** as-needed(中文 `/` 零破坏、英文 `/en`)· **偏好** cookie + 后端 nullable 字段双层。

## 二、i18n 框架选型(Next.js 15 App Router)

- **确认环境**:Next `^15.1.0` + App Router(无 pages/)+ React 19 · 零 i18n 依赖,干净起步。
- **★推荐 next-intl**。理由:① 唯一 **RSC-first**、与 App Router + React 19 天然契合(Server 用 `getTranslations()`、Client 用 `useTranslations()` + `NextIntlClientProvider`);② 单依赖、包体最小(~457B gzip),不违 CLAUDE.md"不早期堆重依赖";③ 维护最活跃(v4.13 @2026-05,周下载 ~180 万,一年 4 倍增长)。next-i18next 的 App Router 支持 2026-03 才补(太新)、react-i18next 需自拼 Server 集成、Paraglide/Lingui 定位偏窄——均不如 next-intl 省心。
- **路由策略**:`localePrefix: 'as-needed'`(中文 `/` 无前缀=**对已上线中文站零 URL 破坏**、英文挂 `/en`、next-intl 自动产 hreflang)。不用 `never`(SEO 无法区分语言变体)、不用 `always`(改动全部现有 URL)。
- **语言偏好存储**:**双层**——① 浏览器 `NEXT_LOCALE` cookie(复用现有涨跌色/显示偏好的 cookie 范式,首屏内联脚本读 cookie 设 `<html lang>`,设置页加语言选择器参考 `ColorPrefSection`);② 后端 `User.language_pref` nullable 字段(alembic `server_default='zh'`,范式同 `avatar_id`/`is_platinum`,登录后跨设备同步)。落地骨架 5 个改动点:next.config 挂 plugin / i18n/request.ts / middleware / `app/[locale]/` 迁移 / messages/{zh,en}.json。

### 3.2 DeepSeek 英文能力(★如实评估,不高估)
**结论:能用、语法正确、信息不丢,但"不够地道到直接甩给海外付费用户当成品"。** 属"合格的技术英文,偶有生硬/翻译腔",需人工润色关键模板,不建议裸奔。
- 翻译/双语是 DeepSeek 相对强项,但强项≠地道;通用英文流畅度/创意写作 GPT-4o 更优,DeepSeek 强在技术域(machinetranslation/byteplus 等对比)。
- 英文写作有"公式化/陈词滥调"倾向(反复用 shadow/echo/whisper 类意象、爱插小标题)——正是海外用户最敏感处。
- **真实"语言串台"bug**(DeepSeek repo Issue #1226:纯英文对话偶尔整段回中文)→ 面向海外产品是硬伤,**必须加语言锁 + 后处理检测**。
- "流畅但错"的幻觉:会产出读着顺但事实/术语错的输出——金融场景术语译错(且很顺)比生硬更危险。
- 定价:deepseek-chat ≈ 输入 $0.14 / 输出 $0.28 每 M token(极便宜)→ **成本不是决策变量,质量和延迟才是**。(注:deepseek-chat 别名 2026/07/24 迁 deepseek-v4-flash,留意 model id。)

### 3.3 双语生成三方案(★推荐 A)
| 方案 | 成本 | 延迟 | 质量 | 判定 |
|---|---|---|---|---|
| **A 按语言各生成一次**(英文用户→全英 prompt→英文分析) | 低(DeepSeek 便宜) | **最优**(无串行) | **上限最高**(用英文生成非翻译·最少翻译腔) | ✅ **推荐** |
| B 生成中文再翻译(LLM/DeepL) | B1 近免费 / B2 DeepL 需付费拍板 | **最差**(串行) | B1 叠加两弱点=Chinglish;B2 对缠论无标准词无能为力 | ❌ |
| C 一次调用出双语 | 省调用 | 输出翻倍变慢 | **最差最脆**(互相污染+解析脆+破坏 4 套 prompt 结构) | ❌ |

**方案 A 具体**:6 类内容每套 system prompt **再出一份英文版**(不是运行时翻译)· Redis 决策卡缓存加 `lang` 分桶(`ai:decision:{sym}:{market}:{period}:{lang}`)避免重复烧 · 是现有"4 套市场 prompt"结构的自然扩展(不引入运行时翻译新接缝——接缝必翻车是项目铁律)。

### 3.4 ★红线:英文"分析非建议"怎么守
现有红线体系 = **3 套全中文机制**:① `rewrite_imperatives`(中文买卖词正则)② `scrub_marketing`(中文禁词表)③ `validate_advisory`+`_ensure_disclaimer`(强制免责嵌入)· 中文禁词/替换 70+ 条 · 英文当前**仅影子推送 4 个词**(buy/sell/long/short)。
- **推荐方案 B:语言感知统一 validator**(不复制英文独立版·维护成本 3 倍)。默认 zh 向后兼容,传 en 走英文规则:英文禁词表 50+ 词(buy/sell/should buy/recommend/target price/guaranteed…)+ **英文免责标准串** + 英文 boll 门禁 + 镜像测试 `test_validator_en.py`。
- **英文免责固定串**(锁死常量,不让 DeepSeek 自由生成):
  > `"The information provided is for informational purposes only and does not constitute investment advice. Nothing herein should be construed as a recommendation to buy, sell, or hold any security."`
- **★硬门**:英文红线校验(Phase 3)必须**先于**英文 AI 输出(Phase 4)上线,否则英文卡片可能缺免责/含 "should buy" 直接踩死红线。

### 3.5 术语表(本次 i18n 核心交付物之一)
- 常规术语有行业标准词直接用:金叉/死叉=**golden/death cross**、多空=**long/short**、超买超卖=**overbought/oversold**、看涨跌=**bullish/bearish**、支撑阻力=**support/resistance**。
- **★缠论是最大坑**(英文社区译法不统一,必须点金自定并锁死):缠论=**Chan Theory**、中枢=**Central Hub**(锁一个)、笔=**Stroke**、线段=**Segment**、分型=**Fractal**、买卖点=**1st/2nd/3rd-type buy/sell point**。不锁死→同一"中枢"这次 Hub 下次 Pivot,用户看懵。
- 术语表两用途:(a) 注入英文 system prompt 作硬约束;(b) 生成后正则校验兜底(尤其免责语 + 语言锁)。

### 3.6 是否换模型(混合)
GPT-4o/Claude 原生英文更地道(客观),LiteLLM 多接一个 provider 技术成本低——**但撞 ① docs/decisions/0003 锁定 DeepSeek ② 涉钱(新 key/账单)**,按协作铁律 §3 是**必须 Hans 拍板的大决策**。**务实路径:先用方案 A + 人工润色英文模板 + 术语表把 DeepSeek 英文压到"可接受";上线后海外反馈不够地道,再把"英文换 GPT-4o/Claude"作独立提案交你拍板(附成本+样本)。本次不夹带换 provider。**

## 五、特殊难点

1. **数字/日期/货币**:前端已用 `Intl.NumberFormat`,但混硬编码中文符号(¥/万/亿)。`format-money.ts` 参数化 locale 即可;`¥` 对中概股保留,`万/亿` 英文用 K/M/B。
2. **图表中文标签**:KLineChart 叠加层 + 缠论 chan-overlay(笔/分型/中枢/买卖点)+ strategy-panel 6 策略标签有中文。缠论 jargon 保留原词 + 英文 tooltip;数学符号(▽△)不译只译 tooltip。

4. **SEO**:as-needed 路由 + next-intl 自动 hreflang;landing force-static SSG 页迁 `[locale]` 后需 `generateMetadata` + hreflang 正确;英文是新增语言、不破坏现有中文收录。

## 九、风险清单(9·按危险度)

1. **★AI 英文踩红线(最高危)**:Phase 4 若先于 Phase 3 上线 → 英文卡片缺免责/含 "should buy" → 违死红线。**英文校验先行、有测试证明才允许英文 AI 输出**。
2. **★LLM prompt 误翻**:有人翻中文时顺手翻了喂 DeepSeek 的 prompt → AI 管道崩。需在这些文件显式标注"DO NOT TRANSLATE"。
3. **覆盖度漏验(项目已有前科)**:同功能多组件(AiDecisionCard vs CryptoAiCard)· 每阶段真机必逐页(cn/us/hk/crypto 详情 + workbench + crypto-preview)。
4. **中英混杂期**:分阶段必然混杂(导航英文、AI 卡仍中文)。
5. **翻译一致性漂移**:717 条 + 后端 + 35 万字若无统一术语表,"A股"时译 A-shares 时译 China A-share。必须先建术语表 v1。
6. **AI 翻译质量**:训练营金融内容 AI 裸翻易错译术语,不能省人工校验。
7. **工作量低估**:两个大头若打包进"加个英文"的模糊估算会严重超期。
8. **M0 阶段错位**:i18n 是否属当前主线。
9. **SEO/URL 破坏 + DB 映射漂移**:路由误选 always 破坏现有 URL;板块静态表上游新增时露中文需 fallback。

---

## 十、混杂期控制策略

核心:**让混杂对用户可预期可接受,不追求某刻 100% 纯净**。
1. **按整页/整功能单元切**,不按半页切——宁可某页整页仍中文,不要同屏半英半中的割裂。
2. **fallback 到英文 + CI 缺 key 检测**:en.json 必须与 zh.json key 对齐,漏译在构建期暴露而非线上露中文。
3. **默认语言零回归**:as-needed 保证中文用户走 `/` 完全不受影响(稳定基线),英文用户走 `/en` 是明确"建设中"空间,两 locale 物理隔离。
4. **AI 遵循"英文校验就位才出英文"硬门**:Phase 3 没上前,英文页 AI 卡宁可回落中文 + 英文"该模块英文版建设中"提示。
