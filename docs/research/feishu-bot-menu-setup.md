## 后端已就绪
`api/v1/feishu.py` 已加 `application.bot.menu_v6` 事件分支:点击菜单 → 取
`event.operator.operator_id.open_id`(已验签身份)→ `event_key` 当 action →
`handle_inbound` → `render_for_feishu` → 后台发新卡。**`event_key` 直接复用现有 action 命名,
核心层零改动。** 配好菜单即生效(发布后等 ~5 分钟)。

## 飞书后台配置步骤
1. 开发者后台 → 选「点金 Midas」应用 → 「添加应用能力」→「机器人」。
2. 机器人配置页 →「机器人自定义菜单」→ 点编辑 → **开启**。
3. 逐个添加菜单项,每项:**响应动作选「推送事件」**,**事件标识(event_key)** 填下表对应值。
4. 「事件与回调」→ 确认已订阅「机器人自定义菜单事件」(`application.bot.menu_v6`),
   回调地址与现有 webhook 同:`https://api.midastrade.asia/api/v1/feishu/webhook`。
5. 创建版本并发布 → 等约 5 分钟,会话左下角出现菜单。

## 菜单项清单(event_key → 对应功能)

**推荐配 4 项**(对齐主菜单核心功能):

| 菜单文案(建议) | event_key(必须照填) | 点击后 |
|---|---|---|
| 📊 行情 | `menu:quote` | 选市场 → 查行情卡 |
| 💼 持仓 | `act:positions` | 我的虚拟持仓 |
| 🛒 下单 | `menu:order` | 下单流程入口(选市场→…→二次确认) |
| 🔔 告警 | `menu:rules` | 告警规则查看 / 启停 / 一键推荐 |

**可选追加**(想要更全):

| 菜单文案 | event_key | 点击后 |
|---|---|---|
| ⭐ 自选 | `act:watchlist` | 我的自选列表 |
| 🌙 安静时段 | `menu:quiet` | 告警安静时段配置 |
| 📋 主菜单 | `menu:main` | 回主菜单(全功能按钮) |

> event_key 必须**逐字**填上表的值(`menu:quote` 等),大小写 / 冒号都不能错 ——
> 它就是后端识别"点了哪个功能"的钥匙。填错 → 后端兜底回主菜单(不会报错,但不是你想要的功能)。

## 红线(已在代码保证,后台配置无需担心)
- **身份**:只认已验签事件里的 `operator.operator_id.open_id`,菜单文案 / event_key 都改不了身份。
- **下单二次确认**:`event_key` 即便误填 `ordok` 也**下不了单** —— execute 仍只由下单流程
  `order_confirm` 态触发;菜单只是入口。(已有测试钉死:伪造菜单 ordok 不成交。)
  → 所以**菜单项不要配 `ordok` / `ordno`**(那是确认卡内部按钮,配了也无效、且无意义)。
- **凭证**:菜单不涉及任何密钥。

> 填 event_key,订阅「机器人自定义菜单事件」,发布等 5 分钟即可。后端已就绪、点了就能用。
