## 命名 · 点金 / Midas

**来源：** 希腊神话米达斯王,触碰之物皆变黄金 —— 点石成金的原型。中文"点金"直接对应"指尖触金"的画面,金融圈无人不晓。

**产品语境：** 用户的核心幻想是"提前看见那个信号" —— 不是真的炼金,而是 AI + 缠论 + 多视角研判帮你把模糊的市场信号变得清晰可执行。点金即点信号,落于纸上、虚拟仓中、复盘里。

**合规外壳：** "模拟点金,不构成投资建议" —— 把"点金"的隐喻封在虚拟资金的安全区内,跟观潮"不下单"同一档合规级别。

## Part 01 · 四个核心决策

动手前必须先定的关键选择。一旦定了就不要改,否则 Manus 跑出来的代码白扔。

### Decision 01 · 技术栈

**放弃 .NET / Blazor,重新用 Python + Next.js 起新项目**

**为什么不在 CryptoSharp 上改？** 观潮所有核心能力的开源轮子(czsc 缠论、AKShare 数据、vnpy 回测、LangGraph AI Agent)都是 Python 生态;前端最好的金融图表(KLineChart Pro)都是 TypeScript 生态。在 .NET 上桥接这些库是花两倍时间。

**CryptoSharp 怎么办？** 保留它作为"加密策略实盘下单"的专属工具(开源版/自托管版),点金 Midas 作为"全市场 AI 分析终端"(订阅 SaaS),**两个产品互不干扰**。CryptoSharp 的业务知识、UI 经验、风控规则 100% 嫁接,**代码 0% 复用** —— 这是上一轮你确认的方向。

**新栈：**

- 前端 `Next.js 15 + Tailwind + shadcn/ui + KLineChart Pro`
- 后端 `FastAPI + Celery + PostgreSQL + ClickHouse + Redis`
- AI 层 `LangGraph + DashScope (通义千问)`

### Decision 02 · 合规边界

**仅虚拟资金,永不接入真实交易通道**

**这是产品 DNA,不是 MVP 阶段的权宜之计。** 所有"点金"动作都是虚拟资金的策略执行,用户体验是"看到买入信号 → 在系统里下虚拟单 → 跟踪策略表现",**从不接券商/交易所的真实下单接口**。

**合规收益：**

- 不需要券商/投顾/基金销售牌照
- 不涉及反洗钱
- 不涉及客户资金托管
- 用户的 API Key 永远不需要填写
- 法律责任停在"工具瑕疵"层面,跟观潮同档

**用户感知：** "模拟点金,不构成投资建议"全站植入。用户根本不在意能不能真下单 —— 他们要的是分析和验证能力。

### Decision 03 · 市场覆盖

**首发三市场：A 股 + 美股 + 加密主流币**

**为什么不只做 A 股？** 观潮被 A 股局限,全球用户接触不到。你天然有 CryptoSharp 的加密圈经验和 Binance 对接能力,**三市场是你对观潮的天然优势**。

**数据范围：**

- A 股全市场 3949+
- 美股 Top 500 + 中概股 + 热门 ETF
- 加密前 100 币
- 日线 + 分钟级

**市场切换：** 用户首页一个 Tab `A 股 | 美股 | 加密`,自选股池跨市场,AI 分析跨市场,虚拟交易跨市场。**这是观潮做不到、传统加密工具做不到的**。

## Part 03 · 完整技术栈

每一层都选了"AI 协作友好 + 开源生态最强 + 中国可访问"的组合。

| 层 | 选择 | 理由 |
|---|---|---|
| 前端 | Next.js 15 + Tailwind | App Router + Server Components + shadcn/ui,AI 写最熟 |
| K 线图表 | KLineChart Pro | 国产开源,70+ 指标 + 完整画线,Apache 2.0,商用 |
| 缠论引擎 | czsc + chanlun-pro | czsc 算法核心,chanlun-pro 参考 UI |
| 后端 API | FastAPI + Pydantic | Python 生态最适合金融 + AI Agent,自动 OpenAPI |
| 异步任务 | Celery + Redis | 数据更新 / 回测 / AI 长任务都用它 |
| 主数据库 | PostgreSQL 16 | 用户/订阅/策略/虚拟仓位等业务数据 |
| 时序数据 | ClickHouse | K 线/Tick 数据专用,比 PG 快 10-100 倍 |
| 数据源 | AKShare + yfinance + ccxt | A 股 / 美股 / 加密三市场对应免费数据 |
| AI 编排 | LangGraph | 多 Agent 协作 + 状态机,比 LangChain 适合金融 |
| LLM 调用 | DashScope + LiteLLM | 通义千问主力,LiteLLM 统一切换 Claude/GPT |
| 支付 | Stripe + 微信支付 | Stripe 主全球,微信支付主国内,双通道 |
| 部署 | Vercel + Cloud Run | 前端 Vercel 全球加速,后端继续 Cloud Run |

## Part 06 · 关键风险与边界

Manus 跑得再快,这些线不能踩。

### ✕ 永远不要接入真实交易通道

这是项目 DNA。哪怕用户哭着求"加个 Binance API Key 让我跟单",都不要做。一旦做了合规复杂度翻 10 倍,"工具软件"身份失效。

### ✕ AI 输出永远带 disclaimer

所有 AI 研判 / 策略建议 / 买卖点标注,必须显式带"仅供参考,不构成投资建议"。法律必须,不是法律建议。

### ⚠ AKShare 数据稳定性

AKShare 爬公开网站,源网站改版会导致接口失效。要写"多源对账 + 自动告警"机制。备份方案:Tushare Pro 积分。

### ⚠ Manus 代码质量需要 Review

AI 写代码会有:

1. 过时 API
2. 漏边界
3. 测试不足
4. 安全漏洞(SQL 注入/XSS)

每个 Milestone 必须人工 Review 才能进下一关。

### ⚠ 不要早期堆功能

观潮宣传 70+ 指标 / 60+ 画线 / 8 种图表 —— 这些都是"长尾"。MVP 做 10 个常用指标 + 5 个常用画线足够。剩下等用户呼喊再加。

### ⚠ "点金"命名的合规边界

"点金"在中文里有"赚钱"暗示,监管会更敏感。配套必须强植入"模拟点金,不构成投资建议",所有营销文案避免"必赚 / 必涨 / 保证收益"。

### ✓ 合规护城河

"仅虚拟交易"给的合规护城河比想象中深。即使将来做美国 / 欧洲市场,"分析 + 虚拟交易"在主要法域都不需要券商牌照。**这是产品长寿的根**。

### ✓ CryptoSharp 业务知识的复利

你对加密虚拟交易 / 风控 / 推送的实战经验全部嫁接过来,起步就比从零做的人快 6 个月。代码 0% 复用换来了 100% 的设计经验复用 —— 这是你独占的优势。
